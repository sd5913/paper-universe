# Paper Universe — Technical Agreement

## 1. Project Goal

Paper Universe is an interactive paper-cut collage experience where players combine visual elements to discover hidden reactions, environmental transformations, and playful surprises.

Our priority is to create a coherent, functional, and visually engaging interactive experience rather than a complex game.

## 2. Shared Technology

All team members will use HTML, CSS, JavaScript, and p5.js to develop a browser-based interactive experience.

The project will be developed using VS Code and managed through our shared GitHub repository.

## 3. Team Responsibilities

Each team member will take ownership of one interactive module:

- **Module A — Weather World:** Weather interactions and environmental changes.
- **Module B — Living World:** Plant growth and living-world reactions.
- **Module C — Secret World:** Hidden combinations and surprising discoveries.
- **Module D — World Experience:** Main interface, player feedback, and navigation.

Every member is responsible for implementing, testing, and documenting their own module.

Integration and final testing will be shared responsibilities.

## 4. GitHub Collaboration

- Each member works on a separate feature branch.
- Each member makes meaningful commits documenting their progress.
- Completed work is submitted through pull requests.
- Changes are reviewed before merging into the main branch.
- Team members update their assigned GitHub Issues regularly.

## 5. AI-Assisted Development

AI tools may support brainstorming, debugging, coding, and documentation.

However, every member must understand, test, and be able to explain their own implementation.

Significant AI assistance, design decisions, and modifications should be documented.

## 6. Integration Rules

All modules must follow shared conventions for canvas dimensions, visual assets, interaction states, and module interfaces.

The team will first develop a small working prototype before expanding the experience.

## 7. Definition of Done

A module is considered complete when:

- Its core interaction works.
- The visual response is understandable.
- The module has been tested.
- Its code has been committed to GitHub.
- It can be integrated with the main experience.
- The responsible member can explain its implementation.
